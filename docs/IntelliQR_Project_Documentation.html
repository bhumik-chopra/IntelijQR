1. Project overview

IntelliQR is a local-first, full-stack QR management platform. It creates styled QR codes, decodes uploaded or webcam QR images, manages dynamic destinations, records privacy-conscious analytics, generates QR codes in bulk, and provides encrypted access-controlled sharing for links and files.

The application is designed as a portfolio-grade multi-user system rather than a single-page QR utility. It includes authentication, owner-isolated records, role-based administration, notifications, profile settings, English/Hindi/Gujarati interface support, and automated backend and frontend tests.

Core idea: the React application presents the user interface, the FastAPI service enforces business rules and security, MongoDB stores records and events, and local directories store generated images, ZIP archives, and encrypted shared files.

Main user groups

  • Public visitors: view the landing page, register/login, follow dynamic QR redirects, and complete protected link/file access checks.
  • Members: generate, scan, manage, export, analyze, bulk-create, and securely share QR-based content.
  • Administrators: view platform statistics, search users, change roles/status, and inspect audit activity.

2. How the project works end to end

Normal authenticated request

1. User acts in a React page
2. Feature API calls /api/v1
3. FastAPI dependency validates JWT
4. Service applies business rules
8. UI updates from typed JSON
7. API returns schema response
6. Repository/storage saves result
5. Renderer/decoder/cipher runs if needed

The frontend uses one API client. It sends cookies on every request, adds the in-memory access token, converts error envelopes to ApiError, and performs a single refresh-and-retry when a protected request returns HTTP 401.

Authentication lifecycle

  1. Registration or login verifies credentials and returns a short-lived JWT access token.
  2. The access token is kept only in JavaScript memory. The refresh token is held in an HttpOnly backend cookie.
  3. On page restoration or an expired access token, POST /auth/refresh rotates the refresh session and supplies a new access token.
  4. Logout, password rotation, account disablement, or security-sensitive role changes invalidate sessions. A token-version check protects every authenticated request.

Dynamic QR lifecycle

  1. A URL QR generation request builds a stable backend URL such as /r/{slug}, rather than permanently embedding the final destination.
  2. The renderer creates PNG, SVG, and PDF files from the persisted BrandCraft design.
  3. When scanned, the redirect endpoint checks status, expiry, scan limit, and access policy.
  4. A permitted scan atomically increments usage, records a privacy-safe analytics event, and redirects to the current destination.
  5. Because the QR contains a stable slug, the owner can change or pause the destination without printing a new code.

3. Feature-by-feature working

FeatureWorking
QR Generator + BrandCraftCreates URL, text, email, phone, Wi-Fi, contact, and location payloads. Users control colors/gradients, modules, frame, correction level, size, margin, and validated logos. Generated items support CRUD, search, filters, favourites, pause/activate, limits, expiry, and PNG/SVG/PDF download.
SafeScanAccepts PNG/JPEG/WebP uploads or webcam frames up to 10 MB. OpenCV/pyzbar decode one or more values. SmartClassifier identifies structured content and SafeScan applies local URL risk heuristics. The source image is not retained.
AnalyticsUses successful dynamic redirect events to calculate totals, unique-visitor estimates, trends, device/browser/OS/location breakdowns, top QR codes, and recent scans. Period and QR filters are supported.
SecureVaultProtects dynamic destinations with public, password, signed-in-member, or private email-allowlist policies. Destinations are encrypted at rest. Successful access produces a short-lived, slug-bound JWT grant before redirect.
BulkForgeParses CSV/XLSX files (up to 250 rows), validates each row through the normal generator, tracks queued/processing/completed/partial/failed state, preserves bounded row errors, and packages successful PNG/SVG/PDF outputs in an owner-only ZIP.
ShareVaultSignature-checks approved files up to 25 MB, encrypts them with AES-256-GCM, generates a recipient QR, and enforces policy, expiry, pause, and atomic download limits. Files are decrypted in memory only after a short-lived access grant.
DashboardAggregates owner-scoped QR, favourite, scan, share, bulk, and export statistics plus recent activity and download history.
NotificationsStores security, scan-limit, ShareVault, and BulkForge events; exposes unread counts and read/delete/preferences controls. Optional email is deliberately restricted to a localhost SMTP capture server.
Profile + i18nUpdates display name, password, theme, and locale. Shared dictionaries provide English, Hindi, and Gujarati UI content, and locale survives session restoration.
AdministrationRole-gated views expose platform counts, paginated user management, role/status controls, and privacy-safe audit history. Rules prevent self-lockout and removal of the last active administrator.

Backend request safeguards

Middleware assigns or preserves X-Request-ID, measures request time, logs completion, and adds API-version and content-type headers. Consistent JSON error envelopes are returned for application, validation, and unexpected errors. CORS allows the local Vite origins and credentials.

Design choices

  • Local-first: no cloud database, file store, translation provider, geolocation API, or external SMTP is required.
  • Feature-oriented frontend: each domain owns its API wrapper, types, and hooks.
  • Layered backend: endpoint, service, repository, and infrastructure responsibilities remain distinct.
  • Stable dynamic links: analytics and destination updates work without regenerating printed QR codes.

8. Security, persistence, and privacy

ConcernImplementation
PasswordsBcrypt-backed password service; plaintext passwords are never stored.
Browser tokensAccess token remains in memory; rotating refresh token uses an HttpOnly cookie.
AuthorizationEvery owner resource is scoped to the authenticated user; admin endpoints require a current database role.
RevocationRefresh sessions plus token-version validation support logout, password rotation, role changes, and disabled accounts.
Protected dataSecureVault destinations and ShareVault files use AES-256-GCM with unique nonces. Shared passwords use hashes.
Temporary grantsPurpose-bound, short-lived JWTs bind access to one QR or file slug.
Scan privacyUploaded images are decoded without retention. Analytics store a keyed one-way visitor hash, not raw IP or full user-agent strings.
Redirect privacyProtected redirects disable caching and referrer propagation to avoid leaking grant information.
Email safetyOnly localhost SMTP hosts are accepted; notification failure never blocks the main operation.

Persisted data

MongoDB collections represented by the repository/model layer include users, refresh sessions, QR generations, scanner history, dynamic scan events, bulk jobs, shared files, share download events, notifications, and audit/dashboard-related events. Local generated artifacts live under the root data/ directory, which is ignored by Git.

Production caution: replace both example secrets, use a dedicated vault encryption key, retain that key safely, set secure cookies behind HTTPS, restrict CORS, and configure MONGODB_REQUIRED_ON_STARTUP=true. Losing or changing the vault key makes existing protected data unreadable.

9. Setup and start commands

Prerequisites

  • Python 3.11+ and Node.js/npm
  • A local MongoDB server reachable at mongodb://localhost:27017
  • Windows PowerShell (commands below); Git is recommended

One-time backend setup

cd C:\codes\react\IntelijQR\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env

Edit backend/.env and replace INTELLIQR_JWT_SECRET and INTELLIQR_VAULT_ENCRYPTION_KEY with separate random values of at least 32 characters. Do not commit .env.

One-time frontend setup

cd C:\codes\react\IntelijQR\frontend
npm install
Copy-Item .env.example .env

Start the application (three terminals)

TerminalCommand
1 — MongoDBStart the local MongoDB Windows service, or run your installed mongod instance.
2 — Backend
cd C:\codes\react\IntelijQR\backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload
3 — Frontend
cd C:\codes\react\IntelijQR\frontend
npm run dev

Open http://127.0.0.1:5173. Swagger API documentation is at http://127.0.0.1:8000/docs; readiness is at http://127.0.0.1:8000/api/v1/health/ready.

Optional administrator

INTELLIQR_ADMIN_EMAILS=["admin@example.com"]

Add the setting to backend/.env, restart the API, then register or log in with that email.

Common problems

SymptomResolution
Backend settings validation failsCreate backend/.env from the example and provide secrets of at least 32 characters.
Readiness returns 503 / operations failStart MongoDB and verify URI/database settings. Enable required-on-startup when failure should stop the API.
Browser cannot call APIConfirm both servers are running, VITE_API_BASE_URL is correct, and the frontend origin is listed in backend CORS settings.
Phone-scanned QR cannot redirectSet redirect/frontend base URLs to the computer's LAN IP; 127.0.0.1 on a phone refers to the phone itself.
Protected data cannot decryptRestore the exact original vault encryption key. Do not casually rotate this key.
PowerShell blocks activationUse .\.venv\Scripts\python.exe directly, or change execution policy only according to local security rules.
Email is not deliveredRun a local SMTP capture service on port 1025, enable user preferences, and keep the host as localhost.
Summary: IntelliQR combines a typed React client with a layered FastAPI/MongoDB backend. Its strongest architectural themes are stable dynamic QR links, explicit feature boundaries, local-first processing, owner isolation, encrypted access workflows, and automated contract validation.
